# Phase 1 導入・操作手順

## ローカルプレビュー

Node.js 22以上とpnpmを使用します。実装時のNodeは24.19.0、pnpmは11.19.0です。

```powershell
pnpm install --frozen-lockfile
pnpm preview
```

サイト： http://127.0.0.1:9400/ 。管理画面： http://127.0.0.1:9400/wp-admin/ 。管理者のローカル認証情報は `.runtime/preview-access.txt` に保存されます。パスワードは起動ごとにランダム化されます。秘密情報のためGitには含めません。

プレビューはWordPress Playground（PHP 8.3 / WordPress 7.1 / SQLite）です。本番用のMySQL構成とは異なります。サイトの編集データは `.runtime/wordpress` に保存します。このフォルダを消すとローカルデータが失われます。コードは `wp-content` 以下のテーマとプラグインです。

9400番ポートはローカル専用です。インターネットに公開するサーバーとして使用しないでください。終了は起動したターミナルでCtrl+C。ローカル検証では外部HTTP通信と自動cronを無効化しています。

## 編集と公開確認

1. 管理者が「都道府県」「市区町村」「サービス」「品目」を確認済みの資料に沿って登録します。市区町村には所属都道府県と自治体コードを指定します。
2. 記事・自治体・業者のメニューから新規登録し、本文と「情報・出典・公開確認」欄を保存します。記事の種類は規定の5種類から一つ選びます。
3. 公開確認担当が編集画面の「保存済みの内容を公開確認する」を開きます。不足項目があれば修正します。
4. 原資料との照合が終わったら確認チェックを付け、「確認済みとして公開」を実行します。

通常の公開ボタンだけでは未確認データを公開できません。本文・構造化情報・分類の変更後は、公開済みでも確認待ちへ戻ります。確認担当・日時・内容ハッシュの履歴を保存します。スタッフ記事は実取材原本の管理番号と掲載許諾、料金記事は調査条件が必要です。

「情報編集担当」は編集まで、「公開確認担当」は確認・公開まで実行できます。管理者は両方を実行できます。「情報確認」画面で最新50件を確認でき、各投稿一覧では確認済み・要確認・90日経過を絞り込めます。

自社サービスも他の業者と同じレコードです。サービス名、公式サイト、対応地域等を確認し、広告・提携区分と運営者との関係を入力してください。企業や自治体の初期実データは登録していません。

## 統合テスト

```powershell
pnpm test
```

テストは9401番ポートと独立した一時WordPressを使います。検証用企業・資料はこの一時環境だけに作られ、プレビューには入りません。結果は `.runtime/test-result.txt` に保存します。テスト用PHPを本番WordPressで実行しないでください。

Windows版Playgroundの一時ファイル処理の競合を避けるため、プレビューを止めてからテストを実行し、テスト終了後にプレビューを起動してください。

## PHP・MariaDB構成（Dockerがある環境向け）

このPCでDocker実行は確認していません。Composeは導入用設定であり、この構成での動作合格を意味しません。

```powershell
./scripts/setup-env.ps1
docker compose up -d
```

http://127.0.0.1:8080/ のWordPress初期設定を完了し、Cleanup CoreプラグインとCleanup Portalテーマを有効化します。パーマリンクは投稿名にします。DBパスワードは自動生成する `.env` に保存し、値をGitやチャットへ転記しません。MariaDB 11.4、WordPress 7.1 / PHP 8.3を指定しています。イメージ入手・起動は未検証です。

停止は `docker compose down`。データを保持するため `-v` を付けません。本番ホスティングにはHTTPS、バックアップ、権限、更新運用を別途設定します。
