# Phase 1 実装状況

更新：2026-09-13

## 実装した範囲

- Cleanup Coreプラグイン：3CPT、5記事区分、地域・品目・サービス分類、構造化入力、出典、確認担当と履歴。
- 公開確認画面：不足・不正データの拒否、権限確認、確認中に内容が変わった場合の競合検出。
- 公開制御：本文・メタ・分類変更時の確認待ち化、REST・直接公開・予約公開経路の検証。
- Cleanup Portalテーマ：指定10セクションのトップ、7カテゴリー、記事・自治体・業者詳細、地域一覧、サービス絞り込み、検索、404。
- 業者の自社・広告・提携区分表示。未登録情報は空表示とし、架空の掲載情報を作らない。
- ローカルWordPress Playground起動、統合テスト、Docker Compose導入設定。

## 設計からの段階的な実装

出典はPhase 1では主資料のURL・名称・日付・対象記述と、追加資料を記入する欄で管理します。設計の複数出典配列・主張単位の検証はPhase 3で拡張します。記事タイプ変更時の旧URL履歴・301、審査済みページだけのindex・Schema・SitemapはPhase 2に残っています。

WordPressの投稿リビジョンと公開確認ハッシュ履歴を保存します。構造化項目の過去値を含む完全な差分監査・復元UIは未実装です。取材原本そのものは保存せず、非公開の管理番号で参照します。

## 検証記録

正式版WordPress 7.1 / PHP 8.3 / Playground SQLiteで、40項目の統合テスト、公開URL13件、404判定2件、認証済み管理画面3件が合格しました。結果は `.runtime/test-result.txt` に保存しています。全PHPファイルの構文解析、正式版のバージョン一致、データ保存、公開確認、変更による公開取消、REST権限、地域整合を含みます。

追加検証でカテゴリー一覧にトップページのテンプレートが選ばれる不具合を検出しました。専用ルート変数と一覧判定を設定して修正し、異なるカテゴリーの記事が混在しないことまで再検証しました。業者詳細では自社・提携表示も確認しました。

取得バージョンの指定が開発候補版へ解決される問題を避け、正式配布ZIPのURLに固定しました。MySQL構成の合格結果としてSQLiteの結果を流用していません。

ローカルプレビューを起動し、ブラウザーでトップページ、業者一覧へのリンク操作と空表示を確認しました。トップの375px・1280px表示を目視し、768pxで横方向にはみ出さないことを確認しました。見出しの不自然な折り返しを修正しました。

MySQL/MariaDBでの実行、全詳細ページの各幅・200%拡大・キーボード操作、本番復元テストは未完了です。Phase 1の全受入条件が完了したとは扱いません。
